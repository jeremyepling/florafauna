Use the shared instructions for checkout ownership, testing and integration. [AGENTS.md](../../AGENTS.md)

1. Choose a base mob and existing feature matching the requested behavior. The Gecko shows how to synchronize a variant with `SynchedEntityData` and persist it with `ValueInput` and `ValueOutput`. Keep the entity, model, renderer, render state and any animation or variant classes in the feature package. [Gecko](../../src/main/java/net/j40climb/florafauna/common/entity/gecko) · [Frenchie](../../src/main/java/net/j40climb/florafauna/common/entity/frenchie)
2. Register the entity type and its resource key in `FloraFaunaRegistry`. For a spawn egg, follow the existing egg registrations using `properties.spawnEgg(...)`. Add its creative-tab entry in `FloraFaunaSetup`. [Registry](../../src/main/java/net/j40climb/florafauna/setup/FloraFaunaRegistry.java) · [Creative tab](../../src/main/java/net/j40climb/florafauna/setup/FloraFaunaSetup.java)
3. Register the mob's attributes, model layer and any required spawn placement in `RegisterEntityEvents`. For natural spawning, check biome placement as well. Register the renderer through `ClientSetup.registerRenderers`. Extract entity state in the renderer and feed that state to the model. [Entity events](../../src/main/java/net/j40climb/florafauna/common/entity/RegisterEntityEvents.java) · [Client setup](../../src/main/java/net/j40climb/florafauna/setup/ClientSetup.java) · [Gecko renderer](../../src/main/java/net/j40climb/florafauna/common/entity/gecko/GeckoRenderer.java)
4. Supply the entity textures and spawn egg resources, check the renderer's texture paths, and add English entries for the entity and egg. The existing model provider generates the Gecko egg as a flat item. For exported models, follow the Blockbench specialist. [Model provider](../../src/main/java/net/j40climb/florafauna/common/datagen/FloraFaunaModelProvider.java) · [Assets](../../src/main/resources/assets/florafauna) · [Blockbench integration](../agents/blockbench-integration.md)
5. Run the applicable build and data checks, spawn the mob in a test world, and verify the requested AI, rendering and persistence. Report any behavior or asset still needing verification.
