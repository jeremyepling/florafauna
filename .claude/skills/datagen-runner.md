Run resource generation in the assigned checkout. The build sequence and parallel worktree conventions are in the shared instructions. [AGENTS.md](../../AGENTS.md)

- Identify the affected registry IDs and expected output. `FloraFaunaDataGenerators.gatherRegistries` supplies recipes, recipe advancements and loot tables. The client datagen run also generates models, tags and wood transformation data maps. Start with the provider for the requested resource. [Data generators](../../src/main/java/net/j40climb/florafauna/common/datagen/FloraFaunaDataGenerators.java) · [Provider directory](../../src/main/java/net/j40climb/florafauna/common/datagen)
- Run `.\gradlew.bat --max-workers=4 runData`. Inspect the relevant files under `src/generated/resources/assets/` and `src/generated/resources/data/`. Fix generated-resource defects in the provider or its source inputs. Check wood-set generation against `WoodType` and hand-authored models against the model provider's inclusion and exclusion logic. [Wood types](../../src/main/java/net/j40climb/florafauna/common/block/wood/WoodType.java) · [Model provider](../../src/main/java/net/j40climb/florafauna/common/datagen/FloraFaunaModelProvider.java)
- Check the IDs and contents of the generated resources. For a visual change, resolve the blockstate or item definition to the intended model and its texture PNGs under `src/main/resources/assets/florafauna/`. Verify resource-loading behavior in the client as needed. [Authored assets](../../src/main/resources/assets/florafauna)
- Once generation finishes, run `.\gradlew.bat --max-workers=4 build runGameTestServer` in a separate invocation so packaging and GameTests see the generated files. Report the affected resource IDs, checks and any unresolved failures.
