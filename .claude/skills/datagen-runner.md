Run resource generation in the assigned checkout. The build sequence and parallel worktree conventions are in the shared instructions. [AGENTS.md](../../AGENTS.md)

- Identify the affected registry IDs. Shared model and loot providers live under `src/main/java/net/j40climb/florafauna/common/datagen/`. The target's `FloraFaunaDataGenerators`, recipe and tag providers live under `versions/<target>/target/java/net/j40climb/florafauna/common/datagen/`. On 26.3, registry datagen supplies the recipes and loot tables, and `WoodTransformsProvider` supplies axe stripping.
- Run `.\gradlew.bat :26.1-neoforge:runData` or `.\gradlew.bat :26.3-neoforge:runData`. Inspect `versions/<target>/build/generated/resources/datagen/` and fix the provider or its inputs. Check wood sets against [WoodType](../../src/main/java/net/j40climb/florafauna/common/block/wood/WoodType.java) and hand-authored models against the [model provider](../../src/main/java/net/j40climb/florafauna/common/datagen/FloraFaunaModelProvider.java).
- Check the IDs and contents of the generated resources. For a visual change, resolve the blockstate or item definition to the intended model and its texture PNGs under `src/main/resources/assets/florafauna/`. Verify resource-loading behavior in the client as needed. [Authored assets](../../src/main/resources/assets/florafauna)
- After generation, run the affected consumer check in a separate invocation so it sees the generated files. Follow the shared guide for the final integration pass. Report the affected resource IDs, checks and any unresolved failures.
